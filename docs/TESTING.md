# 首轮审查修复验证

## 自动验证

使用 JDK 21，执行 `./gradlew.bat build`（Windows）或 `bash ./gradlew build`（Linux/macOS）。
JUnit 通过 NeoForge 的测试启动器加载 Minecraft 类型。

- 会话规则：伪造玩家或会话、越序请求、错误节点/选项、条件失效、命令顺序、重复提交、循环节点、关闭和重新开场。
- 服务端执行入口：没有会话、其他玩家操作、重放和退出后的旧请求均不执行命令；动作打开新对话时，旧对话不会覆盖新会话。
- 网络路由：非空和空的登录同步都只发给指定玩家；显式重载仍广播。覆盖操作包编码与节点 ID 长度限制。
- 图片：仅 PNG 头部即可取尺寸；反复加载复用元数据；缓存有上限；清空后读取新尺寸；成功与失败路径都关闭流。

网络发送与命令执行器在单元测试中使用替身，不等同于真实双客户端联机测试。

## 游戏内验收

以下步骤供使用实际客户端、服务端及整合包时验收；不能据自动测试通过推断这些步骤已实测。

1. 在隔离测试服和两个客户端安装同一份构建产物。旧协议客户端应因协议不匹配而无法使用新服务端。
2. 准备一个有立绘、背景、线性节点、选项及节点命令的测试对话。创建计分板 `vnd_review`，让节点命令使用 `scoreboard players add @s vnd_review 1`，选项命令添加不同标签。
3. 分别通过点击、空格、自动播放、Ctrl 推进线性节点，确认每次合法完成只增加一次分数。选项节点应停下等待选择，选定后执行节点与该选项的命令。
4. A 玩家停留在对话中，B 玩家登录；A 的当前节点与历史应保持不变。管理员执行 `/dialog reload` 更新内容，也不应破坏 A 已开启的会话。
5. 在选项显示后改变其条件，原选项提交应被服务端拒绝，且不执行对应动作。
6. 关闭、断线、重开对话后，旧会话请求应失效。对话命令打开新对话时，新对话应保持可操作。
7. 重复播放大量立绘和背景，重载资源包后验证图片尺寸更新。代码只缓存至多 256 份尺寸，实际游戏纹理仍由 Minecraft 管理；用内存分析器检查时应区分两者。

本轮不包含跨服、跨重启持久化、逐句恢复或发奖事务。会话内重放被拒绝，合法循环和重新开场仍按配置执行动作。
